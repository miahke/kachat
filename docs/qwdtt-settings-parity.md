# Перенос настроек qWDTT в kachat

Проверено по исходникам `work/qwdtt/app/src/main/java/com/wdtt/client/ui/settings/SettingsTab.kt`, `settings/SettingsStore.kt`, `tunnel/TunnelManager.kt` и `profiles/SubscriptionImport.kt` (2026-11-04). Это перенос применимых параметров транспорта, а не системного VPN-интерфейса оригинального приложения.

В kachat qWDTT работает как аутентифицированный SOCKS5 на `127.0.0.1`; Android VpnService не создаётся. Профиль редактируется в блоках «Основные параметры» и «Дополнительные параметры». Импорт сохраняет профиль, подключение запускается отдельной кнопкой. Значение READY означает готовность локального прокси, а не проверенный выход в интернет. Проверка соединения — отдельный HTTPS-запрос через выбранный маршрут.

| Параметр оригинала | Состояние в kachat | Реальное применение |
| --- | --- | --- |
| Название, адрес VPS, пароль, хэш звонка | Перенесены | `peer`, `password`, `hash` → `-peer`, `-password`, `-vk`; секреты хранятся отдельно от профиля |
| WireGuard / защищённый Raw | Перенесены | WG → `-mode socks`; Raw v2 → `-mode rawtun` с локальным userspace-прокси |
| SOCKS5 как отдельный режим оригинала | Адаптирован | Для WG и Raw всегда используется локальный прокси внутри kachat |
| Порт DTLS / прямой RTP / Raw | Перенесены | `serverPort` входит в адрес VPS; авто-режим имеет отдельный `fallbackPort` |
| DTLS / RTP AEAD / автоматический выбор | Перенесены | `-notls` / `-auto-peer -fallback-port` (авто только WG) |
| TURN TCP / UDP | Перенесены | `turnTcp` → `-turn-tcp`; выключенный переключатель означает UDP |
| Переопределение TURN-адреса и порта | Перенесены | `-turn`, `-port`; пустой адрес и порт 0 используют параметры VK |
| Маскировка «аудио» / «видео» | Перенесена | `obfuscation` → `-obfs audio|video` |
| DNS для VK: Яндекс, Cloudflare, Google | Перенесены | UDP и DoH, понятные названия в списке; `dns` → `-go-dns` |
| Свой DNS / DoH | Перенесены | `custom:IPv4[:порт],…` или `doh:https://…/dns-query`; до четырёх адресов |
| DNS внутри туннеля | Поддерживается ядром | `-tunnel-dns`; пусто — сервер; IPv4 через запятую |
| MTU, WG keepalive | Поддерживаются ядром | `-tunnel-mtu`, `-wg-keepalive`; 0 MTU / -1 keepalive — параметры сервера |
| Таймаут рукопожатия / конфигурации | Поддерживаются ядром | `-dtls-timeout`, `-config-timeout` (5–60 с) |
| Таймаут запуска | Поддерживается приложением | Ограничение ожидания готовности процесса 15–300 с; не отдельный CLI-флаг |
| Число транспортных каналов | Ограничено до двух | Ядру всегда передаётся `-n 2`; импортированное `workers` не повышает лимит |
| Локальный порт SOCKS, логин | Перенесены | `-socks 127.0.0.1:порт`, `-socks-user`; порт 1024–65535 |
| Отключение SOCKS-аутентификации / ручной пароль | Изменены для локальной интеграции | Аутентификация обязательна, пароль прокси генерируется и хранится зашифрованным |
| Локальный UDP-порт VPN / отдельный WireGuard-порт Android | Исключены для userspace-прокси | Нет Android VPN и локальной передачи пакетов в VpnService |
| Исключения приложений / IP, обход локальных сетей, обновление bypass-маршрутов | Исключены как системные VPN-настройки | kachat не маршрутизирует трафик других Android-приложений |
| Остановка на Wi-Fi | Не перенесена | Это автоматизация жизненного цикла оригинального приложения, не параметр ядра |
| Интерфейс admin/user, темы/палитры, авто-переход к логам, подробные логи, обновление APK | Не переносятся в настройки транспорта | Используется интерфейс и жизненный цикл kachat |
| Группы профилей, лимиты/расход подписки, периодическое обновление URL-подписки | Не перенесены | Поддерживается локальный импорт содержимого; URL не загружается автоматически |
| Путь анонимной авторизации VK `vkcalls/legacy` | Перенесён | `vkAnonPath` → `-vk-anon-path`; VK Звонки по умолчанию, прежний способ доступен в дополнительных параметрах |
| Аккаунт VK / получение хэша / капча | Отдельный поток авторизации | Не передаются в экспортируемый профиль; вход VK не нужен для готового хэша |

## Импорт и экспорт

Принимаются upstream-ссылки `qwdtt://config?…` и `qwdtt:config?…`, JSON-массивы, объекты `profiles`/`servers`, JSON одного профиля и Base64 этих форматов. `pass/password`, `hashes/vkHashes`, `port/listenPort` совместимы с оригиналом. Поле `port` обозначает локальный SOCKS-порт; удалённый порт задаётся в `peer`. При нескольких хэшах создаются отдельные профили с отдельными идентификаторами устройств, каждый с двумя каналами. Отсутствующий хэш позволяет сохранить профиль и получить его позднее.

Дополнительно принимаются и экспортируются поля kachat: `mode`, `username`, `turnHost`, `turnPort`, `turnTcp`, `noDtls`, `autoPeerMode`, `fallbackPort`, `connectTimeoutSeconds`, `handshakeTimeoutSeconds`, `configTimeoutSeconds`, `tunnelDns`, `tunnelMtu`, `wgKeepaliveSeconds`, `dns`, `vkAnonPath`, `obfuscation` (`obfs` принимается как псевдоним). Оригинальный импортёр qWDTT понимает базовые реквизиты, а эти дополнительные поля игнорирует: импорт обратно в оригинал не переносит расширенные настройки.

Экспорт создаётся только по кнопке «Поделиться ключом» и копируется отдельной кнопкой после пояснения о пароле и хэше. Он содержит секреты доступа к серверу, но не пароль локального прокси, сессию VK, идентификатор профиля или устройства. Импорт/редактирование проверяют диапазоны портов, MTU, таймаутов, допустимые режимы, синтаксис адресов и DNS без сетевых запросов. Подключение не запускается автоматически.
